Choose the right cloud service model by understanding who manages each layer.

Why this matters

The same word hides different jobs

"Cloud" might mean using a finished app, deploying code to a managed platform, or renting a virtual machine. Each choice changes who patches, backs up, monitors and supports the system.

Real consequence: If a school treats an IaaS VM like SaaS, OS patches and backups may be missed because everyone assumes the provider is doing them.

Core concept: the cloud model ladder

SaaS

  • Use a complete application
  • Provider manages app and platform
  • User manages data, access and settings
  • Examples: Gmail, Microsoft 365, Zoom

PaaS

  • Deploy your code to a managed platform
  • Provider manages runtime and servers
  • Developer manages app and data
  • Examples: App Service, Heroku, Cloud Run

IaaS

  • Rent infrastructure building blocks
  • You manage OS, runtime, app and data
  • Provider manages physical data centre layers
  • Examples: AWS EC2, Azure VM
Timing: 5 minutes. Emphasise the movement from convenience to control as you move from SaaS to IaaS.

SaaS: software as a service

Think: subscribe and use

SaaS gives users a ready-made application through a browser or app. You configure settings, manage accounts, protect data and train users.

  • Great for email, documents, CRM, video calls and storage.
  • Fast rollout, little server expertise needed.
  • Less control over app internals and release schedule.

Gmail

Provider runs the mail platform.

Microsoft 365

Users create content and manage sharing.

Zoom

Finished conferencing service.

Timing: 4 minutes. Ask learners which parts of Microsoft 365 they can configure and which parts they cannot touch.

PaaS: platform as a service

Think: bring your code

PaaS is useful when a team wants to build and deploy an application without spending time building servers, patching operating systems or configuring load balancers.

Developer pushes code -> Platform builds -> Platform runs -> Team monitors app behaviour

Azure App Service

Host a web API or website on a managed platform.

Google Cloud Run

Run containers without managing virtual machines.

Heroku

Deploy apps with simple platform workflows.

Timing: 5 minutes. Relate PaaS to a student project: the class writes the API, but the platform handles the server plumbing.

IaaS: infrastructure as a service

Think: rent the building blocks

IaaS gives you virtual machines, disks and virtual networking. It feels closest to running your own server room, except the physical hardware and data centre are provided for you.

You still own key operations

  • Patch and harden the operating system.
  • Plan backups and recovery testing.
  • Monitor CPU, memory, logs and costs.
  • Manage admin access and application security.
Timing: 4 minutes. Explicitly correct the common misconception: renting a VM is IaaS, not SaaS email.

Trade-offs: convenience, control and skill

Convenience

SaaS is quickest because the app already exists. Good for standard business needs.

Control

IaaS gives more control but adds patching, monitoring, backup and security work.

Skills

PaaS needs developers who understand code deployment. IaaS needs infrastructure skills too.

Cost shape

Subscriptions, platform usage and VM resources are priced differently. Check hidden operations time.

Timing: 5 minutes. Ask the class to rank SaaS, PaaS and IaaS from easiest to most flexible, then reveal the trade-off cards.

Worked example: launch a student events app

SaaS route

  • Use Microsoft Forms or SharePoint list
  • Fast and low maintenance
  • Limited custom workflow

PaaS route

  • Build a small web app/API
  • Deploy to Azure App Service
  • Focus on code and data

IaaS route

  • Install web server on Azure VM
  • Patch OS and secure firewall
  • Useful for legacy dependencies
Decision prompt: If the app is a learning project, PaaS usually gives enough control without the overhead of VM administration.

Common faults and fixes

SymptomLikely causeFix
VM is compromised after months onlineIaaS server was treated like SaaS; OS patches were missedAssign patch ownership, enable update management and monitor vulnerability reports
Unexpected cloud billIaaS resources left running or PaaS scaling rules too broadAdd budgets, alerts, schedules and resource tagging
Students cannot access shared filesSaaS permissions or group membership configured incorrectlyCheck group membership, sharing links and conditional access settings

Jargon buster

SaaSSoftware as a Service: a complete application delivered over the internet.
PaaSPlatform as a Service: managed environment where developers deploy code.
IaaSInfrastructure as a Service: rented compute, storage and networking.
Shared responsibilityThe split between what the provider secures and what the customer secures.
RuntimeThe software environment that executes application code, such as Node.js or .NET.
VirtualisationTechnology that lets many virtual machines share physical hardware.
Virtual machineA software-defined computer with its own operating system and resources.
TenantAn organisation's separated space inside a shared cloud service.
ScalingIncreasing or decreasing resources to match demand.
AvailabilityHow reliably a service stays reachable for users.
Vendor lock-inWhen moving away from a provider becomes costly or difficult.
SLAService Level Agreement: provider promise about uptime or support response.
RegionA geographic cloud location that affects latency, resilience and data rules.
Identity and accessControls for who can sign in and what they can do.

Key takeaways

SaaS = use

You use the finished app and manage users, settings and data.

PaaS = build

You bring the application code; the platform handles much of the runtime stack.

IaaS = host

You manage the operating system and applications on rented infrastructure.

Ask "who manages?"

The best model depends on responsibility, speed, control, skills, risk and cost.

Timing: 4 minutes. Ask learners to summarise each model in three words, then compare with the slide wording.
