Service Catalogue

Publish what IT offers, how to request it, and what sits out of scope.

OCN NI Level 2-3 · IT support / service delivery
Timing: 2 minutes. Welcome learners. Frame the session as building a mini school IT catalogue so staff stop emailing random technicians for password resets and laptop loans.

Learning objectives

By the end of this session, you will be able to:

  • Explain what an IT service catalogue is for and why mystery requests waste time.
  • Write clear entries with service name, audience, request path, owner and hours.
  • Design a simple request form with the right fields for triage.
  • Match request scenarios to Standard, Priority or Emergency tiers.
  • Mark out-of-scope items with alternatives and link catalogue language to ticket types.
Timing: 3 minutes. Ask learners for one IT request they have made at school or work, then map it to catalogue, form and ticket language.

Why this matters

Mystery requests create chaos

Without a published catalogue, staff email whoever they know. Password resets and laptop loans bounce between people, work is duplicated, and SLAs are missed because nobody owns the queue.

Real consequence: A school exam week can fail when urgent resets sit unread in a technician's personal inbox.

Core concept: what a catalogue is for

Show the offer

  • List services users can request
  • Use everyday language
  • Reduce "who do I ask?" mystery

Set expectations

  • Who the service is for
  • How to request it
  • Owner and support hours

Draw boundaries

  • Mark out-of-scope work
  • Offer alternatives
  • Link entries to ticket types
Timing: 5 minutes. Emphasise that a catalogue is a user-facing promise, not an internal wiki dump.

Entry fields that make a usable listing

Service name

Clear title in user language, e.g. Password reset — not AD unlock.

Who it is for

Staff, students, visitors, or a named team.

How to request

Portal form, helpdesk email, or phone for emergencies only.

Owner / hours

Named owner and when the service is staffed.

Timing: 4 minutes. Ask the class to rewrite one jargon-heavy service name into user language on a whiteboard.

Practical notes: language, scope, path, owners

User language

Avoid jargon so non-IT staff can find the right service quickly.

Out of scope

Say what you do not do, and point to an alternative when possible.

Request path

One clear channel beats three informal inboxes.

Owners

Someone accountable for quality, updates and escalation.

Timing: 5 minutes. Challenge learners: if a service has no owner, is it really offered?

Service tiers: Standard, Priority, Emergency

Standard (Bronze)

  • Planned or low urgency
  • Example: software install next week
  • Normal queue and SLA

Priority (Silver)

  • Work blocked for a person or class
  • Example: teacher cannot project for a lesson
  • Faster response target

Emergency (Gold)

  • Wide outage or safety/security risk
  • Example: whole-site Wi-Fi down
  • Immediate escalation path
Timing: 4 minutes. Link tiers to the next demo on SLA response times so learners see why catalogue and SLA work together.

Practical task: school mini catalogue

Brief

Build a mini IT service catalogue for a secondary school. Include 6–8 services, at least two out-of-scope items with alternatives, and map each in-scope entry to a ticket type and tier.

  • Use user language in every service name
  • Include audience, request path, owner and hours
  • Mark out-of-scope items with alternatives
  • Link entries to ticket types and tiers

Evidence checklist

  • Completed catalogue table or share link
  • Screenshot of catalogue builder list
  • Form designer score or field list
  • Tier matcher best score
  • Short reflection: what would you publish first?
Timing: 10 minutes. Circulate and challenge any jargon-heavy names or missing owners.

Jargon buster

Service cataloguePublished list of IT services users can request, with how and who.
Service requestA user ask for something IT already offers, such as a laptop loan.
IncidentAn unplanned interruption or quality drop in an IT service.
Out of scopeWork IT does not offer; boundaries and alternatives should be stated.
Service ownerPerson accountable for a service's quality, updates and escalation.
Request pathThe approved channel used to ask for a service.
SLAAgreed targets for response or resolution times.
TriageSorting tickets by impact and urgency so the right work is done first.
Ticket typeCategory used in the helpdesk tool, ideally matching catalogue language.
Priority / tierRelative urgency band such as Standard, Priority or Emergency.
ITSMIT Service Management: practices for designing and delivering IT services.
Knowledge baseSelf-help articles that can sit beside catalogue entries.
EscalationMoving a ticket to a higher skill level or manager when needed.
User languagePlain wording that non-technical staff can understand quickly.
Timing: 6 minutes. Give learners two minutes to search three unfamiliar terms, then ask them to use one term in a sentence about the school case study.
