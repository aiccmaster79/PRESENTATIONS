Why Accessibility Matters

A website is only successful when people can actually use it. Accessibility checks help visitors who use screen readers, keyboard navigation, captions, zoom, high contrast settings, or alternative input devices.

For coursework, you need to show a practical cycle: audit, fix, and retest with evidence. This also supports awareness of the Equality Act and inclusive service design.

Toolkit

Accessibility Audit Toolkit

Click or press Enter/Space to flip each card

Alt text

Describe the purpose of meaningful images. Decorative images can use empty alt text so they are skipped.

Contrast

Text must stand out from the background. WCAG AA normal text target is 4.5:1.

Headings

Use one logical outline. Do not skip from h1 to h4 just for visual size.

Keyboard focus

Every interactive control must be reachable and show a visible focus indicator.

Labels

Inputs need programmatic labels. Placeholder text is not a reliable label.

Link text

Links should make sense out of context. Replace "click here" with a meaningful action.

Have pairs flip all six cards, then explain one card back to the room. Timing: ~6 min.

Audit = Evidence + Judgement

Automated checks

  • Fast scan for missing alt attributes
  • Flags many colour contrast failures
  • Finds empty links or form label problems
  • Generates repeatable scores for evidence
  • Cannot understand image purpose or content quality

Manual checks

  • Tab through the page without a mouse
  • Read headings as an outline
  • Judge whether alt text is useful
  • Check error messages and labels make sense
  • Confirm fixes after changing the code

Portfolio wording: "The audit identified a contrast failure on the CTA. I changed the colours, retested, and recorded the new ratio."

Stress that WCAG is evidence-led: state the issue, impact, and fix. Timing: ~4 min.

Demo Sequence: Basic Audit

  1. Open the demo page and run an automated scan such as Lighthouse or WAVE
  2. Record the initial score and top issues in a short audit table
  3. Tab through the page and check visible focus order manually
  4. Inspect images, headings, labels, link text, and colour contrast
  5. Fix two high-impact issues in the HTML/CSS
  6. Retest and save before/after screenshots for portfolio evidence

Evidence phrase: "Before: grey CTA ratio 2.02:1. After: white on purple ratio passes AA for normal text."

Use this as the audit sequence learners will follow in the practical. Timing: ~6 min.
Case study

Case Study: College Open-Day Page

Further education college Open-day recruitment page Equality Act awareness

A college open-day page looked modern, but applicants reported that the Apply now button was hard to read, a screen reader announced the logo as "image", and the enquiry form relied on placeholder text only.

The web team audited the page, changed the CTA colours to pass contrast, added purposeful alt text to the logo link, paired each input with a visible label, and retested. The final evidence pack showed the original issue, the fix, and the new audit result.

Barrier

Low contrast, missing alt, and placeholder-only form

Audit move

Automated scan plus manual tab and label checks

Fix

Update CSS, alt text, labels, and retest with screenshots

Common Accessibility Faults

FaultImpactFix
Missing altScreen reader users miss the image purposeAdd useful alt, or empty alt for decorative images
Poor contrastText is hard to read for low vision or bright-light usersChange colours until normal text reaches 4.5:1
Skipped heading levelsPage outline becomes confusingUse headings in logical order; style with CSS
Invisible focusKeyboard users lose their placeProvide a clear :focus-visible style
Placeholder-only inputsLabel disappears and may not be announced correctlyUse <label for="..."> tied to input id
"Click here" linksLink purpose is unclear out of contextWrite descriptive link text such as "Download travel map"

Practical Task

Brief: Score the demo page, fix two accessibility issues, and re-audit. Choose alt + label or contrast + focus if you need a tight scope.

Success criteria

  • Initial audit score or issue list recorded
  • At least two issues fixed in HTML/CSS
  • Fixes match the user impact described
  • Retest completed after saving changes
  • Evidence clearly shows before and after

Evidence checklist

  • Screenshot: original audit result or issue
  • Code snippet: changed alt, label, CSS, or focus style
  • Screenshot: retest result after fix
  • One paragraph: why the fix improves accessibility
Circulate and coach evidence capture: screenshot, note, fix, retest. Timing: ~15-20 min.

Jargon Buster

Accessibility
Designing and building so people with different needs can use the site.
WCAG
International guidelines used to judge accessible web content.
Alt text
Text alternative that explains the purpose of meaningful images.
Contrast ratio
Numerical comparison between text and background brightness.
AA
Common WCAG conformance level; normal text contrast needs 4.5:1.
Keyboard focus
The visible position of keyboard navigation on an interactive element.
Label
Programmatic name for an input, often connected with for and id attributes.
Placeholder
Hint text inside an input; it should not replace a label.
Heading hierarchy
Logical order of headings that structures the page.
Screen reader
Software that reads page content and controls aloud or via braille.
ARIA
Extra attributes for accessibility when native HTML is not enough.
Focus trap
A bug where keyboard users cannot leave or navigate a component correctly.
Automated audit
Tool-based scan that flags common issues quickly.
Manual audit
Human checks such as keyboard testing and judging alt text quality.
Semantic HTML
Using elements for their meaning, such as button, nav, main, and label.
Evidence
Screenshots, notes, and code proving the issue was fixed and retested.

A2.0:1
B3.0:1
C4.5:1
D10.0:1 only
Correct: C. Normal text needs at least 4.5:1 for WCAG AA. Timing: ~1 min.

Q3: Why are labels better than placeholders alone?

ALabels make forms slower
BLabels stay available to assistive technology
CPlaceholders are illegal in all cases
DLabels replace validation
Correct: B. Labels remain available to assistive tech when placeholders disappear. Timing: ~1 min.

Q4: A keyboard user needs...

AOnly a mouse hover state
BVisible focus and reachable controls
CAll links removed
DImages instead of buttons
Correct: B. Keyboard users must see where focus is. Timing: ~1 min.

Q5: Heading levels should...

AJump around for visual size
BBe hidden from everyone
CCreate a logical page outline
