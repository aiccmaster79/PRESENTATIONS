Guessing vs Inspecting

Guessing

  • Change random CSS
  • Ignore red Console errors
  • Miss file paths and case
  • Blame the browser without proof

Inspecting

  • Select the exact element
  • Read which CSS rule wins
  • Check status codes
  • Trace errors to line numbers

Rule of thumb: Elements for structure/style, Console for script errors, Network for loading problems.

Ask learners to choose a panel for three quick website symptoms. Timing: ~4 min.

The Inspection Loop

  1. Reproduce with DevTools open.
  2. Choose Elements, Console, or Network.
  3. Collect selector, error text, status code, or screenshot.
  4. Test a temporary live edit if safe.
  5. Apply the real fix in source and refresh.
/* temporary live edit */
                .hero-title {
                  color: #00BDA5;
                }

DevTools edits disappear on refresh; source files hold the permanent fix.

Stress temporary browser edits versus permanent source changes. Timing: ~4 min.

Live Demo Sequence

  1. Open a demo page and right-click the broken area, then Inspect.
  2. Use Elements to identify tag, class, and active CSS.
  3. Live-edit a colour and explain refresh will undo it.
  4. Open Console and read the first red error.
  5. Open Network, reload, and find missing files.
  6. Fix source, refresh, and capture evidence.

Case study

Case Study: Skills Hub

Belfast FE collegeLearner website projectChrome DevTools + source fix

A learner site called Skills Hub had two assessment-day faults: the logo was missing and the navigation went blank after the menu button was clicked.

Network showed img/skillshub-logo.png returning 404; Console showed ReferenceError: toggelMenu is not defined. The learner corrected the image path and renamed the JavaScript call to toggleMenu, then refreshed and captured before/after evidence.

Practical Task

Brief: Inspect the prepared demo page. Live-edit a colour, identify one Console error, spot a 404 in Network, apply the source fix, then collect screenshots.

Success criteria

  • Open DevTools using Inspect, F12, or Ctrl+Shift+I
  • Select an element and explain tag, class, and CSS rule
  • Live-edit colour or spacing safely
  • Identify the Console error and likely source line
  • Find the 404 request and apply a permanent source fix

Evidence checklist

  • Screenshot: selected element with Styles pane
  • Screenshot: Console error before fix
  • Screenshot: Network row showing 404
  • Screenshot or commit: source fix and working page
Circulate and ask learners to explain evidence before accepting a fix. Timing: ~15-20 min.

Jargon Buster

DevTools
Browser tools for inspecting, testing, and debugging a live webpage.
Elements panel
Panel for selecting HTML nodes and seeing applied CSS rules.
DOM
The browser live tree representation of page structure.
Styles pane
Area showing CSS rules affecting the selected element.
Live edit
A browser-only change used to test an idea before editing source files.
Console
Panel that displays logs, warnings, and JavaScript error messages.
ReferenceError
JavaScript error when code uses a name that does not exist.
Network panel
Panel showing files requested by the page, status codes, and sizes.
Status code
HTTP number describing request result, such as 200 OK or 404 Not Found.
404
Status meaning the requested file could not be found.
304
Status meaning the browser can reuse a cached copy.
Device toolbar
DevTools mode for testing common screen widths and device presets.
Sources panel
Panel for viewing loaded code and pausing JavaScript.
Accessibility tree
Browser view of roles, names, and states exposed to assistive technology.
