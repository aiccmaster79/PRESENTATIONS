Why Git Matters

Git records snapshots of your project. You can see what changed, roll back mistakes, and (later) collaborate — essential professional practice instead of renaming zip files forever.

InitStart a local repo
CommitNamed snapshot
LogBrowse history

Consequence

Without history, one bad overwrite can wipe a week of coursework. With commits, you restore the last good snapshot in seconds.

Hook with a story of lost work. Emphasise local Git first. Timing: ~4 min.

Three Areas of Git

Working tree

Your normal files — edit freely in the editor

Staging area

What you’ve marked for the next commit (git add)

Committed history

Saved snapshots with messages (git commit)

Everyday loop: edit → status → add → commit → check log.

Draw the three boxes on the board if helpful. Staging is the concept learners struggle with most. Timing: ~5 min.

Good Commit Messages

Avoid

  • “stuff” / “updates” / “fix”
  • Huge commits with ten unrelated edits
  • Secrets, API keys, .env files
  • Messages that only say “what” with no “why”

Prefer

  • Present tense: “Add input validation for age”
  • One idea per commit
  • Clear enough for future-you
  • Short subject line (≈50 chars)
Have learners rewrite a vague message on mini-whiteboards. Timing: ~4 min.

Demo Sequence

  1. Create a small project folder with one Python (or HTML) file
  2. git init — show that a hidden .git directory appears
  3. Edit the file; git status / git diff to see changes
  4. git add + git commit -m "…" with a clear message
  5. Make a second change and another commit; show git log --oneline
  6. Optional: VS Code Source Control view alongside the terminal
Project your terminal if time allows. Keep the sample to one or two files. Timing: ~7 min.

Case study

Case Study: Aoife’s Coursework

Derry FE college · Level 2 Programming One-week mini project Local Git only

Aoife kept saving project_final.zip, project_final2.zip, and project_USE_THIS.zip on her Desktop. On submission day she opened the wrong zip — an old version missing her validation functions. Panic.

With her tutor she initialised Git in the project folder, made a first commit of the working copy, then committed after each feature (“Add age validation”, “Fix menu loop”). When she broke the menu, git log and a checkout of the previous commit recovered the good version in minutes. Evidence: two commits in git log --oneline plus a short reflection.

Symptom

Wrong zip submitted — features missing

Git move

Init + small commits after each feature

Win

History recovers yesterday’s working code

Named scenario for portfolio language. Ask: “How many zips are on your Desktop right now?” Timing: ~5 min.

Common Git Faults

SymptomLikely causeFix
“not a git repository” Wrong folder, or never ran git init cd into the project folder; run git init
Commit says “nothing to commit” Forgot git add, or no file changes Edit a file, git status, then git add before commit
Author identity unknown user.name / user.email not set Configure name and email for the lab profile once
Huge / secret files in commit Staged .env, binaries, or caches Use .gitignore; never commit secrets — scrub if already pushed
Can’t see history Looking in wrong folder or no commits yet Run git log --oneline after at least one commit

Toolkit

Remotes & History

Flip cards for clone / pull / push · sample log timeline below

Clone

Copy a remote repo (e.g. GitHub) onto your machine — creates a local Git project with history and a link to origin.

Pull

Fetch new commits from the remote and merge them into your current branch — “get the latest from the team”.

Push

Send your local commits to the remote so others (and backup) can see them. Commit first, then push.

Remote

A named URL (often origin) pointing at GitHub/GitLab. Local Git can work without one.

Branch

A parallel line of commits so you can try ideas without breaking main. Covered more in GitHub & CI/CD.

Log

git log --oneline lists commits newest-first — hash + message. Your project’s diary.

a3f91c2Add age validationAoife · today 14:02
7b2e014Add hello scriptAoife · today 13:40
c91d0aaInitial commitAoife · today 13:35

Practical Task

Brief: Create a tiny project folder with one source file. Initialise Git, make at least two commits with clear messages, and capture your history.

Success criteria

  • git init succeeds in the project folder
  • git status used before and after staging
  • At least two commits with clear messages
  • git log --oneline shows both commits
  • No secrets or junk files committed

Evidence checklist

  • Screenshot: git status with staged/untracked files
  • Screenshot: git log --oneline with 2+ commits
  • Short note: why staging before commit helps
  • Optional: VS Code Source Control screenshot
Circulate and fix git config / wrong directories early. Collect screenshots for portfolios. Timing: ~15–20 min.

Jargon Buster

Git
Distributed version control system that stores project snapshots as commits.
Repository (repo)
A project folder tracked by Git — includes the hidden .git directory.
git init
Creates a new local repository in the current folder.
Working tree
The files you see and edit in the project folder.
Staging area
The set of changes marked to go into the next commit.
Commit
A saved snapshot of staged changes with a message and unique hash.
git status
Shows which files are changed, staged, or untracked.
git add
Copies changes from the working tree into the staging area.
git log
Lists commit history — use --oneline for a short view.
git diff
Shows line-by-line differences in unstaged (or staged) changes.
Clone
Download a remote repository and its history to your machine.
Pull
Get new commits from a remote into your current branch.
Push
Upload your local commits to a remote repository.
.gitignore
File listing patterns Git should not track (e.g. .env, caches).
Commit hash
Short ID (e.g. a3f91c2) that uniquely identifies a commit.
Learners can search during the quiz. Highlight staging vs commit. Timing: ~3 min.
