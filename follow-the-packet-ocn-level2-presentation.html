Follow the Packet

Wrap a message, walk it hop by hop, and feel the difference between a fat pipe and a quick one.

OCN NI Level 2 Diploma in Information Technology
Welcome the group. Tell them this lesson is a journey, not a list of definitions: one click becomes headers, hops, and a wait. Point at the three activities coming up — wrap, predict, then choose a link. About 2 minutes.

Learning objectives

By the end of this session you will be able to:

  • Name the three addresses a computer uses: name, IP address, and MAC address
  • Wrap a message in the right order: segment, packet, then frame
  • Predict what a switch, a router, and NAT each do to a packet
  • Choose a link for a job by comparing bandwidth and latency
  • Explain a “the internet is broken” ticket that is really delay, not a dead connection
Read the five objectives. Ask who has said “the Wi-Fi is down” when a page still loaded. That story returns in the case study. About 3 minutes.

A click is a journey

Opening a page feels instant. Between your laptop and the server the message is wrapped, renamed, and handed from device to device. When something feels “slow” or “down”, you are debugging that journey.

Three ways to name a computer

Name

portal.example is for people. DNS turns it into an IP address before a packet can be addressed.

IP address

192.168.10.25 is the logical address on this network. Routers forward packets by destination IP.

MAC address

3C:22:FB:… is burned into the network interface. Switches forward frames to a MAC on the local link only.

Same laptop, three labels. Use the name with a person, the IP with a router, and the MAC with a switch. Mixing them up is how “it works on the IP but not the name” tickets start.

Write the three labels on the board as learners say them. Use portal.example — the .example domain is reserved for teaching. About 4 minutes.

Four layers you can actually see

Posters sometimes show seven OSI layers. The packet you can describe in class carries four. Each layer adds a header and does not replace the one inside it.

LayerWhat it addsClassroom example
ApplicationThe message itselfGET /index.html
TransportA port, and TCP or UDPTCP port 443 for HTTPS
InternetSource and destination IP192.168.10.25 → 203.0.113.50
LinkSource and destination MAC, for this hop onlyThe switch’s job

203.0.113.50 is a documentation address. It stands in for “a public server” so we never invent a real one.

Do not make them memorise OSI numbers today. The four rows are the ones the next widget builds. Mention that a router strips the link header and writes a new one for the next cable. About 4 minutes.

Ports are door numbers

An IP address finds the computer. A port finds the program listening on it. HTTPS, DNS, and a lab printer can share one machine because they use different doors.

PortUsual serviceWhy you care
443 / TCPHTTPSThe padlock in the browser

53 / UDP or TCPDNSNames become IP addresses

Use the apartment analogy once, then drop it. Emphasise 443 versus 80, because the quiz asks. Printing stays on the LAN in the theatre activity. About 3 minutes.

Wrap the message

Build the parcel from the inside out. A wrong layer shakes — that header goes on later.

Outside — what this cable carries — is the top bar

Let a learner drive. If they grab Ethernet first, pause on the shake and say “the cable header is the wrapping paper, not the gift.” When it completes, say the next router will throw the frame away and build a new one. About 6 minutes.

On the LAN, the switch uses MAC

One local link

A switch learns which MAC sits on which port and forwards the frame only there. It does not read the website name.

ARP finds the next MAC

If the destination IP is on your subnet, ARP asks “who has this IP?”. If it is elsewhere, ARP asks for the gateway’s MAC instead.

A lab printer stays home

Same subnet means the frame never needs NAT or the internet. The IP finds the printer. Port 9100 finds the print service.

Draw two PCs and a printer on one switch. Then draw a cloud beyond the router. Ask which job needs the gateway. ARP is “the shout across the room”, not a routing protocol. About 3 minutes.

The gateway and NAT

Your laptop often has a private address — 10.x, 172.16–172.31, or 192.168.x. The public internet does not route those. The default gateway is the router that knows the way out.

Private source

192.168.10.25 is meaningful only on this LAN.

NAT rewrites it

The router swaps that source for its public address and remembers the mapping.

The reply comes home

Return traffic hits the public address. NAT looks up the map and delivers it to your laptop.

The destination IP of the website stays the website. NAT changes your source address. That is why many laptops can share one college connection.

Act it out with two learners sharing one “public” name badge. The router is the person at the door who remembers who asked. About 4 minutes.

Routers, hops, and TTL

Frames are local

Each router removes the Ethernet header, reads the destination IP, and builds a fresh frame for the next link.

TTL counts hops

Every router subtracts 1 from Time To Live. At 0 the packet is dropped, so a routing loop cannot spin forever.

Delay adds up

Each hop costs a little time. Bandwidth can still be huge. Latency is the wait, not the width of the pipe.

Traceroute maps a path by sending packets with TTL 1, then 2, then 3. The router that drops each one reports back. You will try a short trace in the practical.

TTL is a safety counter, not a timer in seconds, despite the name. If someone asks about traceroute, keep it to “increasing TTL, authorised on a network you are allowed to test.” About 3 minutes.

Packet theatre

Pick a journey. Answer before the packet moves. A wrong guess still teaches — the note underneath is the reason.

Run the website journey together, then hand the keyboard over for the printer and the call. Ask why the printer never lights the ISP node. Celebrate predictions, including the misses. About 6 minutes.

Case study: games night

Harbour College runs a Friday games night. This is a composite classroom case — typical faults, not a news report. The organiser says the internet is down because the match is unplayable.

What they saw

  • Ranked match full of rubber-banding
  • YouTube 1080p still played
  • Speed test about 40 Mbps
  • Ping swinging from 40 ms to 400 ms

What it meant

  • Bandwidth was enough for the game
  • Latency and jitter were the fault
  • Video can buffer; a live match cannot
  • The access point sat on a busy 2.4 GHz channel

What fixed it

  • Match PCs moved to wired ports
  • The AP moved to a clearer 5 GHz channel
  • The ticket was closed as delay, not “no internet”
Say out loud that Harbour College is a teaching composite. Ask which number disproved “the internet is down” — the 40 Mbps result. Link forward to the Wi-Fi channels deck for the radio part. About 4 minutes.

Practical: trace one click

On a classroom PC you are allowed to use, follow one website request only as far as your gateway and a name lookup. Do not scan other people’s machines.

Success looks like

  • You can point to your IP, subnet mask, and default gateway.
  • You can say whether a name became an IP.
  • You can mark one job as “bandwidth” or “latency”.

Evidence checklist

Jargon buster

PacketData plus an IP header. Routers forward packets using the destination IP.
FrameA packet wrapped with a link header, usually Ethernet MAC addresses, for one hop only.
SegmentThe transport wrapper. TCP segments and UDP datagrams carry a source and destination port.
EncapsulationAdding a header around data. The sender wraps inside-out; each hop may replace the frame.
IP addressThe logical address of a host on a network, such as 192.168.10.25.
MAC addressThe hardware address of a network interface. Switches use it on the local link.
PortA number that picks a service on a host. HTTPS is usually TCP 443.
DNSThe directory that turns a name such as portal.example into an IP address.
NATNetwork Address Translation. A router shares one public IP by rewriting private source addresses.
Default gatewayThe router a host sends to when the destination is not on the local subnet.
ARPAddress Resolution Protocol. On a LAN it finds the MAC address for a known IP.
TTLA hop counter in the IP header. Routers subtract one. At zero the packet is dropped.
BandwidthHow much data can flow, often in Mbps. It decides how fast a large file finishes.
LatencyHow long a packet takes to arrive. Live calls and games feel this immediately.
TCPA transport protocol that checks delivery and resends loss. A good fit for web pages and email.
UDPA transport protocol that does not resend. Often used for voice, where a late packet is useless.

Key takeaways

Wrap inside out

Message, port, IP, then a MAC frame for this hop only.

Different devices, different addresses

Switches read MAC. Routers read IP. NAT rewrites the private source.

Ports pick the program

443 is the usual HTTPS door. The IP only finds the machine.

Mbps is not delay

A fat, slow link downloads files and still ruins a live call.

Four pillars, one sentence each. Ask the room to finish “a switch uses…”. About 2 minutes.

Career pathways

IT support

First line for “no internet” tickets. You separate DNS, DHCP, and delay before you escalate.

Network technician

Cabling, switching, Wi-Fi, and evidence. College, council, NHS, and local IT employers all hire this skill.

Network engineer

Routing, firewalls, and design. This deck is the vocabulary those jobs assume you already have.

Progression in Northern Ireland often runs through the Level 2 diploma, then an apprenticeship or a higher network course. The practical sketch is portfolio evidence.
