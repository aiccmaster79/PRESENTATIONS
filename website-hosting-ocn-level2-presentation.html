Why Hosting Matters

Hosting places your website files on a web server so other people can reach them using a URL. For a static website, the host serves your HTML, CSS, JavaScript, images, and fonts exactly as files.

URLShareable evidence
HTTPSSecure delivery
404Path needs fixing

Professional habit

A site is not finished when it works from file://. It must work from the live URL on another device.

Use the file URL vs HTTPS distinction as the hook. Show a local path and a live URL if possible.

Hosting Toolkit

Hosting

A service that stores website files and serves them to visitors over the web.

Static vs dynamic

Static sites serve files; dynamic sites run server code or database logic for each request.

DNS / URL

The human-readable address that points users to the hosted site or project.

HTTPS

Encrypted web delivery that protects users and avoids browser security warnings.

index.html root

The default home page file must normally sit at the publish root of the project.

Cache

Browser or CDN saved copies can make old files appear after you deploy a fix.

Let learners flip the six terms. Pay special attention to index.html root and cache because they cause practical delays.

What Hosting Does

Local folder

  • Files open with file:// on your computer
  • Links may work even with relaxed local behaviour
  • No public URL for a tutor or client
  • Phone testing requires copying files or using a server

Hosted site

  • Files served from a web server using https://
  • Case-sensitive Linux paths often expose mistakes
  • Public URL can be tested and submitted as evidence
  • Cache and publish-folder settings can affect results

Static hosting is ideal for portfolios, landing pages, prototypes, and HTML/CSS/JS coursework without server-side databases.

Compare local and hosted behaviour. Mention that static is enough for this unit unless a brief requires server code.

Better publish root

published-site/
  index.html
  about.html
  css/style.css

Many hosts look for index.html at the root. If it is inside an extra folder, the live home page may be 404.

Ask learners to identify which folder should be dragged into the host or selected as publish directory.

Demo Sequence: Static Deploy

  1. Run a local smoke test: home page, About page, CSS, images, and one JavaScript interaction.
  2. Choose a static host such as Netlify, GitHub Pages, or the school web space.
  3. Upload the project so index.html is at the publish root.
  4. Open the live HTTPS URL in a fresh tab and test the home page.
  5. Hard refresh and test links that move between folders.
  6. Open on a phone, take screenshots, and record the live URL for evidence.

Evidence habit: submit the live URL, a phone screenshot, and a short note explaining any 404 you fixed.

Demonstrate with a tiny static site. Narrate every check so learners can copy the sequence.
Case study

Nested Folder to Live Site

Static portfolio Netlify-style upload Linux host paths

A learner published a folder called portfolio-final that contained another folder named website. The live URL showed 404 because the host could not find index.html at the root. After moving the files up one level, the home page worked.

The About page still failed because the link used About.HTML but the file was about.html. The Linux host was case-sensitive, unlike the learner's local computer.

Fault 1

index.html buried inside a nested folder

Fault 2

Path case mismatch: About.HTML vs about.html

Result

Files moved to root; paths corrected; live URL evidenced

Make the case study concrete by sketching the folder tree. Ask learners to predict the second fault before revealing it.

Practical Task: Deploy, Break, Fix

Brief: Deploy the demo folder to a static host. Verify the live URL on desktop and phone. Then intentionally break one path, observe the 404, fix it, redeploy, and capture evidence.

Success criteria

  • index.html is at the publish root
  • Live URL opens using HTTPS
  • CSS, images, and internal links load correctly
  • At least one phone or responsive check completed
  • Broken path 404 is explained and fixed

Evidence checklist

  • Live URL copied into portfolio
  • Screenshot: desktop home page
  • Screenshot: phone or responsive view
  • Short note: 404 cause and fix
Circulate while learners deploy. Watch for uploading the parent folder instead of the project contents.

Jargon Buster

Hosting
Service that stores and serves website files over the web.
Static site
Site made of files served as-is, usually HTML, CSS, JavaScript, and assets.
Dynamic site
Site that generates pages using server code or database queries.
URL
The web address visitors use to request a page.
DNS
System that points domain names to the servers hosting a site.
HTTPS
Encrypted web connection that browsers mark as secure.
index.html
Default file a host serves for a folder or site root.
Publish root
The folder the host treats as the top level of the live site.
404
HTTP response meaning the requested file or route was not found.
Cache
Saved copy that can make old files appear after a new deploy.
Relative path
A link from one project file to another without a local drive path.
Case-sensitive path
Host treats About.html and about.html as different files.
Deploy log
Host output showing what was uploaded, built, or failed.
CDN
Network that serves cached site files from locations near users.
Encourage learners to search for 404, cache, root, and relative path while troubleshooting.

Q1: What is the purpose of website hosting?

ATo store and serve website files at a URL
BTo write all HTML automatically
CTo replace CSS
DTo validate spelling only
Correct answer: A. Hosting makes files available over the web.

Q2: A live home page shows 404 immediately after upload. What should you check first?

AWhether index.html is at the publish root
BWhether the logo is blue
CWhether the page has comments
DWhether the font is installed locally
Correct answer: A. Missing root index is a common first fault.

Q3: Static hosting is best suited for...

AHTML, CSS, JavaScript, and image portfolios
BA complex server database app only
COperating system updates
DPrivate passwords in source code
Correct answer: A. Static hosts are ideal for coursework portfolios.

Q4: HTTPS means...

AThe connection is encrypted
BThe site cannot have bugs
CThe folder is automatically correct
DImages are compressed
Correct answer: A. HTTPS secures transport; it does not prove correctness.

Q5: Why is index.html important?

AIt is often the default page served from the site root
BIt deletes old cache files
CIt changes DNS records
DIt turns CSS into JavaScript
Correct answer: A. Hosts commonly look for index.html as the home page.

Q6: After redeploying, a browser still shows the old CSS. Likely cause?

ACache
BDuplicate ID
CMissing alt text
DWrong doctype
Correct answer: A. Hard refresh or clear cache before deeper debugging.
