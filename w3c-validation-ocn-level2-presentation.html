Why Validation Matters

HTML validators check your markup against web standards. They catch mistakes browsers may quietly repair, such as missing closing tags, duplicate IDs, broken document structure, and image rules that affect accessibility evidence.

Use a quick example: browsers forgive messy HTML, validators document it. Stress that clean validation helps assessment and maintenance.

W3C

The World Wide Web Consortium publishes web standards so pages work consistently across browsers and tools.

Validator

A tool that checks HTML against rules and reports line numbers, errors, warnings, and hints.

Error vs warning

Errors usually mean invalid markup. Warnings are guidance, but they still deserve a conscious decision.

Well-formed

Elements are opened, nested, and closed in a valid order without stray tags.

Doctype

The declaration that tells the validator the document uses modern HTML, such as <!doctype html>.

Alt attribute

Text alternative for an image. It supports accessibility and may be required for portfolio quality.

What the Validator Checks

Markup structure

  • Required document parts such as <html>, <head>, and <body>
  • Legal elements and attributes for the selected HTML version
  • Correct nesting, closing tags, and no stray end tags
  • Unique IDs so scripts, labels, and anchors target one element

Quality signals

  • Missing alt attributes on images
  • Deprecated or obsolete attributes
  • Language, encoding, and viewport clues
  • Warnings that may not block evidence but need judgement

Key point: W3C validation is not the same as accessibility testing, but invalid HTML can cause accessibility tools to fail or misread the page.

Clarify scope: validator checks markup, not every design or accessibility issue. Link to accessibility-audit as a sibling skill.

Applied Example: Why One Tag Matters

Broken snippet

<main>
  <section class="portfolio">
    <h2>My project</h2>
    <div class="card">
      <img src="site.png">
      <p>Evidence screenshot</p>
  </section>
</main>

Likely messages

  • Image element missing required alt text for evidence quality
  • Unclosed <div> before closing </section>
  • Cascading messages may point after the real mistake
  • Fix source, save, re-run validator, then screenshot
Do not solve everything immediately. Ask learners which message they would fix first and why.

Demo Sequence: Validation Workflow

  1. Open the local demo page in the browser and confirm the page you will evidence.
  2. Open the W3C Markup Validation Service and paste, upload, or enter the URL.
  3. Read the first error carefully: line number, element, and message.
  4. Fix the cause in your source file, save, and validate again.
  5. Repeat until zero errors, then consider warnings and accessibility follow-up.
  6. Screenshot the clean result with file name, date, and page visible if required.

Evidence habit: include the fixed source, the clean validator report, and one sentence explaining a fault you corrected.

Model the workflow with a prepared page. Keep the validator open and show how one fix can reduce several messages.
Case study

Portfolio Page: Failed to Evidence-Ready

Level 2 website unit Assessment portfolio HTML + CSS evidence

A learner's portfolio page looked fine in Chrome but failed validation. The report showed an unclosed <div>, an image without alt, and a duplicate id used by two sections. The learner fixed the unclosed tag first, which removed three cascading errors, then added descriptive alt text and renamed the second ID.

The final screenshot showed zero errors in the W3C validator and became part of the evidence pack with the corrected source code.

Symptom

Many validator errors from one open container

Method

Fix the first cause, save, then re-validate

Evidence

Clean report screenshot plus fixed HTML

    Jargon Buster

    W3C
    Organisation that develops open web standards used by browsers and validators.
    Markup Validation Service
    The W3C tool that checks HTML and reports standards issues.
    Doctype
    Declaration at the top of the document that tells tools which HTML standard to use.
    Element
    A piece of HTML such as a heading, paragraph, image, or section.
    Attribute
    Extra information on an element, such as src, alt, or id.
    Alt attribute
    Text alternative that communicates image purpose to assistive technology.
    Error
    A validator message that normally means the HTML does not meet the selected standard.
    Warning
    A message that may not invalidate the page but should be reviewed.
    Nesting
    The order elements open and close inside each other.
    Unclosed tag
    An element that starts but is not closed in the correct place.
    Duplicate ID
    Two or more elements using the same ID, which breaks unique targeting.
    Cascade
    Several messages caused by one earlier markup fault.
    Evidence screenshot
    Image of a clean report used to prove validation work.
    Good-enough evidence
    A clean, relevant, dated or clearly identifiable artefact that matches the assessment task.
    Invite learners to search for terms while fixing. Point out duplicate ID, cascade, and good-enough evidence.
