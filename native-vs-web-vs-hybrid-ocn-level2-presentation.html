Why the Choice Matters

The build approach affects what the app can do, how fast it feels, how often it can update, who can maintain it, and whether the team hits the deadline. The best choice depends on requirements, not fashion.

FeaturesDevice APIs and offline needs
CostTeam skills and codebases
UpdatesStore review or web deploy

Decision rule

Start with the problem, users, devices, and constraints; then choose the technology.

Native

Built for one platform using its SDK and language, such as Kotlin/Java for Android or Swift for iOS.

Web / PWA

Runs in the browser, can be installable, and updates from the server without store review.

Hybrid

Uses web technologies inside a native shell, often sharing one codebase across platforms.

WebView

A native component that displays web content inside an app wrapper.

Store distribution

Publishing through app stores brings review rules, fees, signing, ratings, and update delays.

Cross-platform

A strategy to share code or skills while still shipping to multiple devices.

Concept: Three Routes

Native

Best fit for high performance, polished platform feel, and deep device APIs; can mean separate Android and iOS codebases.

Web / PWA

Best fit for content, forms, fast updates, broad reach, and lower distribution friction; device access varies.

Hybrid

Best fit when a team wants app-store presence and shared web skills, with some native plugins.

native = platform SDK | web/PWA = browser + install features | hybrid = web app inside native shell
Compare approaches through performance, device features, distribution, updates, offline needs, and staffing.

Case Study: School Notices App

Small teamChanging contentMissed deadline

A school wanted notices, lunch menus, event reminders, and a few forms. The team chose native Android and native iOS because "apps feel official", but they had one web developer and only six weeks.

They missed the launch window. A web/PWA or lightweight hybrid approach would have reused web skills, shipped faster, and handled frequent notice updates without store-review delays.

Lesson: a technically powerful option can still be the wrong option for deadline, staffing, and update needs.

Discuss the school notices case study and what assumptions led the team toward the wrong choice.

Jargon Buster

Native app
App built with platform-specific SDKs and languages for Android or iOS.
Web app
App delivered through a browser using web technologies.
PWA
Progressive Web App: web app enhanced with installability, caching, and app-like features.
Hybrid app
App using web code inside a native shell, often with plugins for device APIs.
WebView
Native component that renders web content inside an app.
SDK
Software Development Kit: platform tools, libraries, and documentation.
Store distribution
Publishing through app stores with signing, review, rules, and fees.
Cross-platform
Sharing code or framework across multiple platforms.
Offline support
Ability to keep working with poor or no network connection.
Device API
Platform feature such as camera, GPS, Bluetooth, sensors, or notifications.
Maintenance cost
Ongoing effort to fix bugs, update dependencies, and support platforms.
Codebase
The source code set a team maintains.
Plugin
Bridge that lets hybrid code call native device features.
Trade-off
A compromise where gaining one benefit creates another cost or limit.

Key Takeaways

Native

Best for performance, polish, and deep device access when budget supports it.

Web/PWA

Best for broad reach, fast updates, simple content, and low distribution friction.

Hybrid

Best when shared code, app-store presence, and moderate native features align.

Trade-offs

Justify the choice with evidence, constraints, and accepted risks.

Summarise core takeaways and ask learners to state one best-fit scenario for each approach.
