What Is a Trace Table?

A trace table is a paper (or spreadsheet) dry-run of code: each row is a step; columns hold variables and any output. It trains you to think like the computer — before you trust the Run button.

Row= one step
Column= one variable
Outputwhen print runs

Tip

Use one column per variable. Update only what changes on that line — leave others blank or carry forward clearly.

Hook: “When did you last predict output wrong?” Emphasise prediction skill over memorising syntax. Timing: ~4 min.

Myth buster

Dry-Run Myths

Click or press Enter/Space to flip each card

“Only for exams”

Myth. Developers dry-run loops on paper or whiteboards during code review — same skill, different stationery.

“Fill every cell”

Myth. Only update columns that change. Carry-forward or leave blank — be consistent so a partner can follow.

“Output every row”

Myth. The Output column stays empty until a print (or similar) actually runs on that step.

“Skip the if test”

Myth. Note the condition result (True/False). That decision explains which branch — and which rows — come next.

“Never run the code”

Myth. Trace first to predict; then run or debug to confirm. Mismatches teach you where your model was wrong.

“One Notes column”

Myth. One column per important variable beats a messy notes dump. Clarity = fewer marking mistakes.

Pairs flip two cards each and teach back. Challenge the “never run” myth gently. Timing: ~6 min.

Worked Example Trace

n = 3
total = 0
while n > 0:
    total = total + n
    n = n - 1
print(total)
StepntotalOutput
Init30
Loop 1 body23
Loop 2 body15
Loop 3 body06

Read the loop carefully: each body does total += n then n -= 1. When n becomes 0, the while stops and print shows 6.

Demo Sequence

  1. Show a short Python snippet (loop + accumulator) on screen
  2. Draw blank columns: Line / var1 / var2 / Output
  3. Learners fill the table in pairs without running the code
  4. Reveal the completed table row by row; discuss disagreements
  5. Run the code (or step in the debugger) to confirm
  6. Change one line (e.g. start value) and re-trace — emphasise prediction skill

Stretch: change n = 3 → n = 4 and ask for the new final output before anyone presses Run.

Project your paper or spreadsheet template. Keep variable names short (n, total, i). Timing: ~6 min.
Case study

Case Study: Aoife’s Loyalty Points

Belfast FE college · Level 2 Programming 40-minute practical Paper trace → Python confirm

Aoife wrote a short loyalty script: start with points = 0, loop while visits > 0, add 10 points each visit, then decrement visits. She expected 30 for three visits but her first live run printed 40.

Instead of sprinkling prints, the tutor asked for a four-column trace. Row 3 showed she had written points = points + 10 and an extra points += 10 outside the loop “just in case”. The unexpected row made the double-add obvious. Evidence: photo of the marked table plus the corrected file.

Symptom

Output 40 instead of 30 — one free +10

Trace move

Row-by-row points column revealed the extra add

Fix

Remove duplicate; re-trace then re-run → 30

Named scenario for portfolio language. Ask: “Where would a debugger have paused?” Timing: ~5 min.

Common Trace Faults

SymptomLikely causeFix
Final output blank forever Forgot the print step, or print is inside a never-true branch Add a row for the print; check the condition that guards it
Variable “jumps” without a line Skipped a statement or merged two steps into one row One meaningful change per row; re-read the source line order
Loop never ends on paper Missed the decrement / update that moves the loop variable Highlight the update line; verify it runs each iteration
Table matches code but live differs Tracing an old version, or different start values Confirm the same file and inputs; re-trace from a clean table
if branch traced but never taken Condition evaluated wrong (e.g. > vs >=) Write True/False for the test before filling branch rows
Keep this up during the practical as a help desk sheet. Timing: ~4 min.

Practical Task

Brief: On paper (or the fillable widget), complete a full trace for the demo loop with n = 3. Then change the start value to n = 4, re-trace on a fresh table, and confirm both finals with a live run or debugger. Collect evidence.

Success criteria

  • Columns for n, total, and Output
  • Init row shows n=3, total=0 before the loop
  • Each loop body updates total then n
  • Final output predicted as 6 (n=3) and 10 (n=4)
  • Live run or debugger confirms both predictions

Evidence checklist

  • Photo or scan of completed n=3 table
  • Second table for n=4 (or clear edits marked)
  • Screenshot of matching program output
  • One sentence: where a wrong row would show a bug
Circulate and coach column discipline. Collect photos for portfolios. Timing: ~15–20 min.

Jargon Buster

Trace table
A table used to dry-run code: rows are steps, columns are variables/output.
Dry-run
Working through a program on paper (or mentally) without executing it yet.
Variable
A named value that can change; usually gets its own column in a trace.
Accumulator
A variable that builds up a result (e.g. total) across loop iterations.
Iteration
One pass through a loop body — often one or more rows in the table.
Condition
A True/False test that decides whether a branch or loop body runs.
Output column
Where you record what the program displays when a print/output statement runs.
Carry-forward
Leaving a cell blank or repeating the previous value when that variable did not change.
Logic error
Code runs but does the wrong thing — often spotted when a table row surprises you.
Off-by-one
Loop or index is short/long by one — classic cause of wrong final totals.
Initialisation
Setting starting values (e.g. total = 0) before the loop — first table rows.
Debugger confirm
Using breakpoints/step to verify that live values match your paper predictions.
Pseudocode
Informal step description; you can still build a trace from clear pseudocode.
Program state
The current values of all variables at a moment — what one table row captures.
Learners can search during the quiz. Highlight dry-run, accumulator, carry-forward. Timing: ~3 min.
